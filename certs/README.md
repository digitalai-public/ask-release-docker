# Production CA trust artifacts

This directory holds the generated CA trust material consumed by the three
CORE services (release-assistant, release-mcp, llm-service-api). Both files
are generated by `install-internal-ca.sh` (root of the repository) and are
**gitignored** — they are deployment-specific, not source-of-truth.

| File | Consumed by | Format | Source of trust material |
|---|---|---|---|
| `cacerts.jks` | release-assistant (JDK truststore via `JAVA_TOOL_OPTIONS`) | Java KeyStore | Local JDK `cacerts` (preferred) **or** `eclipse-temurin:17-jdk-alpine` fallback + operator's corporate CA chain |
| `ca-bundle.pem` | release-mcp, llm-service-api (OpenSSL bundle via `SSL_CERT_FILE`) | PEM bundle | `certifi` system CAs + operator's corporate CA chain |

See `README.md` §28 for the install procedure, lifecycle, and rotation
guidance.

## Bootstrap order

1. Place the operator's corporate CA bundle at a path on the host
   (e.g. `/etc/ssl/corp-ca-bundle.pem`).
2. Run `./install-internal-ca.sh /etc/ssl/corp-ca-bundle.pem` from the
   repository root.
3. Verify both files are non-empty and parse cleanly
   (see `README.md` §28.4 verification steps).
4. Restart the CORE services:
   `docker compose -f docker-compose.yaml --profile with-llm-service
   restart release-assistant release-mcp llm-service-api`.

## JDK truststore source

`install-internal-ca.sh` builds `cacerts.jks` from a local JDK's `cacerts`
when one is available. The resolver walks the following paths in order and
stops at the first hit:

1. `${JAVA_HOME}/lib/security/cacerts` (if `JAVA_HOME` is set)
2. `/opt/java/openjdk/lib/security/cacerts`
3. `/usr/lib/jvm/*/lib/security/cacerts` (Debian/Ubuntu)
4. `/usr/local/openjdk-*/lib/security/cacerts` (tarball installs)

If none match, the script falls back to `docker pull
eclipse-temurin:17-jdk-alpine` and extracts the in-image `cacerts`. This
fallback requires outbound Docker Hub access; in environments that block
docker.io, install a local JDK (any JDK 11+ — `keytool` is already required
by the script) so the local path is taken.

## Rotation

Re-run `install-internal-ca.sh` with the rotated CA bundle. The script is
idempotent — it overwrites the JKS and PEM with the new content and resets
both files to mode `0600`. Restart the CORE services to pick up the new
trust material.
